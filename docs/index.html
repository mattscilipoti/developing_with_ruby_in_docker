What is Docker? 🐳

Docker is a platform for developing, shipping, and running applications in containers.

Containers Explained

  • Lightweight, standalone packages
  • Include everything needed to run an application
  • Isolated from other containers and the host system
  • Consistent across different environments

Docker vs Virtual Machines

Containers

  • Share host OS kernel
  • Lightweight (MBs)
  • Start in seconds
  • More efficient

Virtual Machines

  • Full OS per VM
  • Heavy (GBs)
  • Start in minutes
  • More isolated

Why Docker for Ruby Development? 💎

Key Benefits

  • Consistent Environment - Same setup across all machines
  • Easy Onboarding - New developers start in minutes
  • Version Management - Run multiple Ruby versions easily
  • Clean Host System - No local gem conflicts
  • Production Parity - Dev matches production closely

Common Challenges Solved

  • "It works on my machine" syndrome
  • Ruby version conflicts
  • System dependency issues
  • Complex setup documentation
  • Database and service configuration

VS Code DevContainers

Development Containers make it easy to develop inside Docker containers

What are DevContainers?

  • VS Code extension for container-based development
  • Full-featured development environment in a container
  • Configuration as code
  • Shareable and reproducible

How It Works

  1. Define your dev environment in .devcontainer folder
  2. VS Code builds and runs the container
  3. Your editor connects to the container
  4. All development happens inside the container
  5. Files are synced automatically

Prerequisites

  • Docker Desktop installed
  • VS Code installed
  • Dev Containers extension installed

Extension ID: ms-vscode-remote.remote-containers

Setting Up Your First Ruby DevContainer

Step 1: Create Configuration

Create a .devcontainer folder in your project root


mkdir .devcontainer
cd .devcontainer

Step 2: devcontainer.json

Main configuration file


{
  "name": "Ruby Development",
  "image": "mcr.microsoft.com/devcontainers/ruby:3.2",
  "customizations": {
    "vscode": {
      "extensions": [
        "rebornix.ruby",
        "castwide.solargraph"
      ]
    }
  },
  "forwardPorts": [3000],
  "postCreateCommand": "bundle install"
}

Step 3: Open in Container

  1. Press F1 or Ctrl+Shift+P
  2. Type "Dev Containers: Reopen in Container"
  3. Wait for container to build
  4. Start developing!

Alternative: Using Dockerfile

For more control, create a custom Dockerfile


FROM ruby:3.2

# Install dependencies
RUN apt-get update && apt-get install -y \
    build-essential \
    libpq-dev \
    nodejs \
    && rm -rf /var/lib/apt/lists/*

# Set working directory
WORKDIR /workspace

# Install gems
COPY Gemfile* ./
RUN bundle install

devcontainer.json with Dockerfile


{
  "name": "Ruby Development",
  "build": {
    "dockerfile": "Dockerfile"
  },
  "customizations": {
    "vscode": {
      "extensions": [
        "rebornix.ruby",
        "castwide.solargraph",
        "kaiwood.endwise"
      ]
    }
  },
  "forwardPorts": [3000],
  "postCreateCommand": "bundle install"
}

Working with DevContainers

Running Ruby Commands

Use the integrated terminal - it's already inside the container!


# Run Ruby scripts
ruby app.rb

# Use bundler
bundle exec rake db:migrate

# Start Rails server
rails server

# Run tests
rspec

Adding Services (PostgreSQL, Redis)

Use Docker Compose for multi-container setups


# docker-compose.yml
version: '3'
services:
  app:
    build: .devcontainer
    volumes:
      - .:/workspace
    ports:
      - "3000:3000"
    depends_on:
      - db
  db:
    image: postgres:15
    environment:
      POSTGRES_PASSWORD: password

Update devcontainer.json


{
  "name": "Ruby with PostgreSQL",
  "dockerComposeFile": "../docker-compose.yml",
  "service": "app",
  "workspaceFolder": "/workspace",
  "customizations": {
    "vscode": {
      "extensions": [
        "rebornix.ruby",
        "castwide.solargraph"
      ]
    }
  },
  "forwardPorts": [3000]
}

Best Practices 🌟

Configuration Management

  • Version control your .devcontainer folder
  • Document any manual setup steps
  • Use postCreateCommand for automation
  • Keep configurations minimal and focused

Performance Tips

  • Use named volumes for gems/node_modules
  • Leverage Docker layer caching
  • Don't mount system files unnecessarily
  • Use .dockerignore file

Security Considerations

  • Don't commit secrets in configuration
  • Use environment variables for sensitive data
  • Keep base images updated
  • Run as non-root user when possible

Team Collaboration

  • Share DevContainer configurations in the repo
  • Document any local-only settings
  • Use consistent base images across team
  • Test configurations on different platforms

Common Issues & Solutions

Container Won't Build

  • Problem: Build fails with dependency errors
  • Solution: Check Dockerfile syntax, verify base image
  • Tip: Use F1 → Show Container Log

Slow Performance

  • Problem: File operations are slow
  • Solution: Use named volumes for dependencies
  • Mac/Windows: Consider consistency settings

Port Already in Use

  • Problem: Can't forward port 3000
  • Solution: Stop local services or change port mapping
  • Config: Update forwardPorts in devcontainer.json
